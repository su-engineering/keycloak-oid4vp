# Keycloak OID4VP 0.2.0

Wallet login for Keycloak 26.8 with OpenID4VP, SD-JWT VC and mDoc. This version moves the extension to Keycloak 26.8, adds sign-in through the browser's Digital Credentials API (including the ISO mdoc protocol used by Safari and Apple Wallet), and broadens issuer trust to XML trusted lists, the EU list of trusted lists and VICAL. It also contains a security review of the whole verification path. It does not establish a long-term support policy or claim HAIP or OpenID conformance.

## Included

- **Keycloak 26.8.** Built and tested for Keycloak 26.8.0 and 26.8.1. The identity provider ID is now `oid4vp-wallet`, so the extension can run next to Keycloak's own experimental OID4VP verifier.
- **Digital Credentials API.** "Use a wallet in this browser" with OpenID4VP (`dc_api`, `dc_api.jwt`, signed and unsigned requests) and ISO/IEC 18013-7 Annex C (`org-iso-mdoc`), with HPKE-encrypted responses bound to the configured origin.
- **Issuer trust.** ETSI TS 119 602 lists of trusted entities, ETSI TS 119 612 XML trusted lists and the EU list of trusted lists, VICAL for mDoc issuers, optional ISO 18013-5 certificate profile checks, and OCSP/CRL revocation checks for issuer certificates.
- **Revocation.** Token Status Lists in JWT and CWT form.
- **Relying party certificates.** The EUDI registration certificate is sent in `verifier_info`, and mismatches with the access certificate or the requested claims are logged.
- **did:web.** Key authorization through `assertionMethod` and the did:web path layout.
- **Identity scope.** `identityKeyScope=issuer` keeps equal identifiers from different issuers apart.
- **Security review.** Issuer binding, mDoc claim handling, origin binding, completion codes, single-use responses, outbound fetch restrictions, cache isolation and input limits were tightened. See the changelog.

## Downloads and validation

Choose the JAR matching your Keycloak version, **26.8.0** or **26.8.1**, using **Java 21**. The release workflow runs unit, cryptographic, packaging and Docker/browser integration tests separately for each target before publishing its JAR. `SHA256SUMS` covers both JARs.

Rename the selected file to `keycloak-extension-oid4vp.jar`, replace the previous provider JAR in Keycloak's `providers/` directory, then run `kc.sh build`. Install only one copy of this provider. See the [installation guide](https://github.com/su-engineering/keycloak-oid4vp/blob/v0.2.0/docs/installation.md).

## Upgrading from 0.1.0-rc.1

This version has breaking changes. Read the [migration guide](https://github.com/su-engineering/keycloak-oid4vp/blob/v0.2.0/docs/migration.md) before updating. In short:

- Upgrade Keycloak to 26.8.x and run `scripts/migrate-provider-id.sql` against a backed-up database.
- Configure `trustListSigningCertPem`; unsigned trust lists are rejected.
- SD-JWT issuer certificates must name the `iss` value in their subjectAltName.
- did:web documents must list signing keys under `assertionMethod`; path DIDs use `<path>/did.json` unless `didWebLegacyPathLayout=true`.
- Set `dcApiOrigin` (or the realm Frontend URL) to offer the Digital Credentials API.
- Set `allowPrivateNetworkFetch=true` if issuers serve status lists, DID documents or metadata from an internal network.
- Store the verifier private key in Keycloak's vault (`${vault.<name>}`) instead of the identity provider configuration.
- Restart in-flight logins after upgrading.

## Known limits

Automated tests use synthetic issuers and the eudi-dev test wallet. The ISO mdoc protocol was tested against published test vectors and a simulated wallet, not with Apple Wallet, which also needs a reader certificate from Apple Business Connect. No published VICAL and no wallet enforcing the EUDI relying party rules were used in testing. SD-JWT claims disclosed as array elements are not resolved for claim mapping, and DCQL `trusted_authorities` is sent to wallets but not enforced on responses. Acceptance testing with your issuers and wallets is still required before promotion. See the [readiness plan](https://github.com/su-engineering/keycloak-oid4vp/blob/v0.2.0/docs/enterprise-readiness.md).
